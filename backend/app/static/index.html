اتاق فرمان لید

از ورود وب‌هوک تا قبول یا رد انسانی. هر دکمه یک مسیر واقعی است: رد اعتبارسنجی، سرد، گرم، داغ + تأیید/رد پیش‌نویس.

    سناریوهای قابل توضیح

    این همان چرخهٔ کاری است که برای واحد فروش خودکار می‌شود: داده خراب وارد CRM نمی‌شود، مدل فقط طبقه‌بندی می‌کند، اولویت را کد محاسبه می‌کند، و پیام مشتری بدون تأیید انسان ارسال نمی‌شود.

      چی توضیح بدهم؟

      1. مسئله: لید خام از فرم/سایت بدون اولویت وارد فروش می‌شود.
      2. n8n ارکستراسیون است؛ FastAPI منبع حقیقت CRM و امتیاز است.
      3. اگر داده ناقص باشد، قبل از دیتابیس رد می‌شود.
      4. خروجی LLM با اسکیما چک می‌شود؛ اولویت را مدل ذخیره نمی‌کند.
      5. داغ → پیش‌نویس؛ انسان قبول یا رد می‌کند. مشتری هنوز پیامی نگرفته.
      6. تلگرام نتیجه تیم فروش است؛ اگر ربات نباشد، skip صادقانه است نه موفقیت جعلی.
