# نمونه‌کار ۱ — اتوماسیون صلاحیت لید فروش (قابل اجرا)

مخزن: https://github.com/mohammadbourbour/AI-CRM  
داشبورد زنده: `http://localhost:8000` بعد از `docker compose up --build`

این متن را می‌توانید در فرم جاب‌ویژن / ایمیل به «بازرگانی رز» بچسبانید. لحن صادق است: دموی قابل ارزیابی، نه ادعای CRM تولیدی مشتری.

## مسئله اولیه

لید خام از فرم/وب‌هوک وارد فروش می‌شود. بدون اولویت مشخص، بدون کنترل کیفیت داده، و بدون دروازه انسان، یا کار تکراری دستی زیاد می‌شود یا پیام اشتباه برای مشتری می‌رود.

هدف: کارهای تکراری صلاحیت و مسیریابی را خودکار کنیم، ولی ارسال پیام به مشتری را قفل نگه داریم تا انسان تأیید کند.

## ابزارها

n8n 2.x (ارکستراسیون، AI Agent، Telegram، WhatsApp، Google Sheets) · FastAPI + SQLite (منبع حقیقت CRM) · OpenAI / Gemini با fallback و Mock صادق · Docker Compose · Git · داشبورد دمو روی `http://localhost:8000`

## نقش من

طراحی فرایند، مدل داده، قوانین قطعی اولویت، گردش n8n، کنترل خروجی LLM، HITL، کانال تلگرام برای نتیجه تیم (نه پیام مشتری)، تست pytest، مستندسازی و نسخه‌بندی.

## نحوه اجرا (۵ دقیقه روی لپ‌تاپ)

```powershell
copy .env.example .env
docker compose up --build
```

باز کنید: http://localhost:8000 — مسیر **ارسال به n8n** را انتخاب کنید. n8n باید Publish شده باشد. جزئیات صبح: [MORNING_RUN_FA.md](MORNING_RUN_FA.md)

سناریوها را یکی‌یکی بزنید و توضیح دهید:

| دکمه | چه اتفاقی می‌افتد | جمله کلیدی برای مصاحبه |
|------|-------------------|------------------------|
| رد اعتبارسنجی | داده ناقص قبل از CRM می‌میرد | صحت داده قبل از هوش مصنوعی |
| Cold | امتیاز سرد، بدون پیش‌نویس | همه لیدها ارزش تماس فوری ندارند |
| Warm | امتیاز گرم، پیگیری سبک | اولویت را مدل ذخیره نمی‌کند؛ کد محاسبه می‌کند |
| Hot | پیش‌نویس HITL | پیام مشتری قفل است |
| قبول پیش‌نویس | `mock_sent` / در صورت تنظیم، WhatsApp | ارسال فقط بعد از تأیید |
| رد پیش‌نویس | `skipped`، CRM qualified می‌ماند | انسان می‌تواند مسیر را متوقف کند |

اگر `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` کانال را بگذارید، **نتیجه تحلیل** (نه متن مشتری) به کانال می‌رود. بدون توکن: `skipped_unconfigured` — موفقیت جعلی نیست.

n8n: ایمپورت `n8n/workflows/lead-qualification.json`، Publish، سپس همان لید از `/webhook/lead-intake`.

نگهداری: Git برای نسخه · pytest برای رگرسیون · `.env` برای خاموش‌کردن کانال‌ها · لاگ با ایمیل ماسک‌شده · idempotency روی `external_id`.

## آنچه این نمونه‌کار برای رز پوشش می‌دهد

- شناسایی کار تکراری صلاحیت لید و اولویت‌بندی بر اثر (داغ اول)
- n8n + API + Webhook + JSON + secret
- LLM با اسکیما، retry، و رد خروجی ناقص (HTTP 503، لید retryپذیر)
- ثبت سوابق در SQLite و داشبورد
- جلوگیری از عملیات تکراری (`external_id`)
- هشدار/گزارش به تلگرام در صورت تنظیم
- Docker و مستندات فارسی/انگلیسی
- آموزش کاربر غیرفنی: چهار دکمه سناریو

## آنچه ادعا نمی‌کنم

این مخزن **پورتفولیوی قابل اجرای من** است، نه CRM در حال کار روی سرور مشتری رز و نه اتصال زنده به وردپرس آن‌ها. برای ارزیابی عملی کوتاه، همین دمو کافی است: رد، قبول، گرم/سرد/داغ را زنده نشان می‌دهم.

## نمونه‌کار ۲ (باید مال خودتان باشد)

آگهی حداقل دو نمونه‌کار می‌خواهد و یکی باید در محیط واقعی استفاده شده باشد. این پروژه را به‌عنوان نمونه‌کار فنی قابل ارزیابی بفرستید. دومی را از کاری که واقعاً اجرا کرده‌اید بنویسید (حتی یک فلو n8n کوچک روی داده غیرمحرمانه). اگر دومی محرمانه است: دمو بدون داده مشتری + توضیح فنی.

قالب دومی:

1. مسئله واحد (مثلاً ورود سفارش/موجودی/پیگیری)
2. ابزار (n8n / API / وردپرس / CRM)
3. نقش شما
4. اجرا و نگهداری (زمان‌بندی، خطا، دسترسی)
5. نتیجه: چه کار دستی کم شد — فقط اگر عدد واقعی دارید
